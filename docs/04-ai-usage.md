# 04 AI 使用说明

## 使用的工具

- **Claude Code**（模型 Claude Opus 5.5），在 Claude 桌面 App 中使用。

## AI 完成的部分

| 内容 | 说明 |
|---|---|
| 选题分析 | 对比四道题的验收点、风险和工作量，建议选第 1 题 |
| 方案设计 | 工具划分、护栏设计（save_draft / finish 两处）、幂等键设计、事实字段由代码生成 |
| 代码初稿 | `src/` 全部模块、`scripts/record_examples.py` |
| 合成数据 | `data/` 下的素材、规则、排期 |
| 测试 | `tests/` 下 29 个用例 |
| 文档初稿 | README 与 docs/01–05 |

## 协作流程：我 + AI

本项目采用"我决策，AI 实现"的人机协作方式完成：我负责方向和取舍，Claude Code 负责设计、编码、测试和文档。

| 阶段 | 我 | AI（Claude Code） |
|---|---|---|
| 读题选题 | 提供四道题的题面；比较后选定第 1 题 | 拆解各题的验收点，对比风险、工作量和业务贴合度，给出建议 |
| 方案与实现 | 确认采用原生实现、OpenAI 兼容接口的方案 | 设计工具和护栏，编写 `src/`、`tests/`、`data/` 和文档 |
| 真实模型验证 | 选择 DeepSeek 作为真实模型，提供并配置 API key | 执行两轮运行，分析偏差 |
| 问题修复 | 确认第一轮暴露问题的修复方向 | 定位并修复 4 个问题，补充回归测试（见 docs/03） |
| 交付 | 确认提交，并推送到 GitHub | 整理提交内容，检查密钥没有进入仓库 |

## 验证方式

- `python -m pytest -q`：29 passed。
- Mock 运行记录：`examples/mock/`，12 个场景。
- 真实模型（DeepSeek deepseek-chat）跑了两轮。第一轮暴露 4 个问题，修复后第二轮 12 个场景全部符合预期。详见 docs/03。

在 Claude Code 完成初始实现后，另使用 Codex 对照题面进行代码审查和文档补充。Codex 检查了 GitHub 中的实现与运行记录，并复跑离线测试和 Mock 场景；没有在本次审查中调用真实模型。

| 环节 | Codex 辅助内容 | 可检查的产物 |

修复代码来自此前的修复提交；本次文档补充没有增加业务功能或生成新的真实模型实验结果。AI 生成和改写的说明同样需要由提交者理解并核对。

## 个人贡献的表述边界

上表中的选题、方案确认和修复方向确认沿用项目原有的协作记录。代码、测试、调试和文档中由 AI 完成的工作不能转述成个人独立实现。本次新增内容也属于 AI 辅助整理，不据此增加个人编码或人工测试贡献。

用于面试说明时，应结合具体代码解释：模型如何得到工具观察、为什么改期需要确认、请求键为什么不含 confirmations，以及保存失败后为什么不能给出 scheduled。能够解释这些设计，和声称独立完成全部实现，是不同的贡献描述。

## 数据与凭据处理

运行数据均为合成资料，不包含真实素材、版权凭证或业务排期。真实模型模式会将请求和工具返回发送至配置的模型接口，因此接入真实业务前应审查字段范围。当前提交只提供 .env.example 占位配置；不得将本地 .env 或真实密钥加入仓库。
