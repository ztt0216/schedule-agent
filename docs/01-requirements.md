# 01 需求

## 用户与目标

- **用户**：内容运营团队的排期负责人。
- **目标**：输入一批待处理素材和各自的发布诉求（渠道、日期、时间）。Agent 要为每个素材给出以下结果：
  - 审核状态
  - 风险原因
  - 建议时段
  - 待确认事项
  - 一份无冲突的排期**草稿**

  最终是否发布，由人决定。

## 输入

| 输入 | 来源 |
|---|---|
| 排期请求：`items[]`（material_id、channel、date、time），可选 `confirmations`（用户已确认的时段） | `examples/requests/*.json` |
| 素材元数据、授权登记 | `data/materials.json`（合成数据） |
| 审核规则 | `data/rules.json` |
| 已有排期 | `data/schedule.json`，可用 `--schedule` 替换 |

## 范围

**包含：**
- 素材读取
- 规则检查
- 授权补查
- 时段查询与替代时段建议
- 草稿保存（幂等）
- 两轮确认：第一轮输出待确认项，第二轮带上 `confirmations` 再跑一次

**不包含：**
- 真实发布
- 界面
- 线上部署
- 多 Agent
- 跨日期自动改期（改日期也属于硬性要求，只能请求用户补充）

## 关键约束（来自题目）

1. 未经用户同意，不得擅自改变硬性发布要求。替代时段只能先标记为 `pending_confirmation`；当前实现直接拒绝在草稿中变更渠道或日期。
2. 只保存草稿，不得称为"已发布"。
3. 相同请求重复保存，只产生一份草稿。
4. 保存失败必须明确返回失败。
5. 设置步数上限，达到上限时返回明确的未完成状态。

## 成功标准

| 验收点 | 期望行为 |
|---|---|
| 正常排期 | 时段可用且无风险时直接标记 `confirmed`；授权待核验的素材先补查，核验通过后再排期 |
| 素材信息缺失 | 返回 `need_info`，并列出具体缺失字段；不做规则检查，不写草稿 |
| 规则风险 | `block` 级风险阻断；授权过期阻断；`confirm` 级风险标记待确认 |
| 时段冲突 | 18:00 被占用时建议 19:00 并标记待确认；用户确认后更新为 `confirmed` |
| 重复提交 | 只产生一份草稿：内容相同则不写入，内容变化则在同一草稿上升级版本 |
| 保存失败 | `task_status=save_failed`，`draft.status=failed`，存储中没有任何写入 |
| 关键缺陷不出现 | 不出现越权发布，不虚报保存成功（由结构约束及已覆盖的护栏测试验证，不代表穷尽所有输入） |

## 业务问题与处理原则

内容运营的排期工作同时依赖素材完整性、审核规则、已有占用和用户授权。仅给出一个可用时间不足以完成任务：如果版权仍待核验，或用户没有同意改期，即使时间空闲也不能把它当作已确认安排。因此，本项目把“审核是否通过”“排期是否确认”“草稿是否写入”分别记录，避免一个笼统的成功状态掩盖问题。

处理以单个素材为单位给出结论，以整批请求为单位保存草稿。某项素材缺信息或被阻断时，其他符合条件的素材仍可进入草稿；结果必须保留所有请求素材的结论。这里的成功是完成审核和草稿交付，不代表发布，也不保证每一项素材最终都能排期。

## 输入契约与示例

请求文件使用 JSON，当前演示按每个素材 ID 对应一项发布诉求组织。时间采用 `HH:MM`，日期采用 `YYYY-MM-DD`；时段依据合成排期配置限制在 08:00–23:00 的整点。

```json
{
  "items": [
    {"material_id": "M01", "channel": "douyin", "date": "2026-11-03", "time": "18:00"}
  ]
}
```

当用户接受 19:00 的建议时，保留原始 `items`，增加 `"confirmations": {"M01": "19:00"}`，再使用同一个草稿存储文件运行。原始诉求保留了幂等身份，确认信息用于更新草稿的排期状态。

`confirmations` 是调用方提供的确认结果。本项目没有登录、审批人鉴权或电子签署流程，不会自行证明传入的确认确实来自有权限的人员。日期、渠道变更当前会被保存护栏拒绝；需要调用方提供新的请求，不能仅靠模型修改草稿字段完成。

## 输出字段与业务含义

| 层级/字段 | 含义与使用方式 |
|---|---|
| `items[].review_status` | 素材审核事实，如 passed、missing_info、blocked、pending_check、needs_confirmation；与排期结论分别判断 |
| `items[].decision` | scheduled、pending_confirmation、blocked、need_info 或 unresolved；scheduled 仅表示草稿排期成立 |
| `items[].risk_reasons` | 规则命中、授权问题以及模型给出的相关风险说明 |
| `items[].suggested_slot` | 本次保存成功的草稿中的渠道、日期和时段；保存失败时为空 |
| `items[].unsaved_suggestion` | 尝试保存但未成功的建议，不能当作已保存排期 |
| `items[].pending_questions` | 需要用户补充、确认或后续重试的事项 |
| `draft.status` | saved、failed 或 not_saved；是否保存成功的事实依据 |
| `published` | 恒为 false；本项目不执行发布 |

`task_status` 用于判断整批请求的后续处理：`completed` 表示处理结束且没有待补充/待确认/未解决项；`awaiting_user` 表示需补充或确认；`save_failed` 表示以正常结束流程报告了存储失败；`incomplete` 表示仍有 unresolved 项或执行达到步数上限。全部被合理阻断也可以是 completed，含义是审核处理完成，而非全部排期成功。判断时应结合各项 decision 和 draft.status。

## 合成数据覆盖设计

| 素材 | 数据特征 | 验证意图 |
|---|---|---|
| M01 | 元数据完整；18:00 有已有占用 | 检查冲突调整、确认边界与重复提交 |
| M02 | 元数据完整，无合成规则风险 | 正常排期与同批时段协调 |
| M03 | 缺封面地址和授权 ID | 请求补充具体字段 |
| M04 | 标题含合成规则中的禁用词 | 阻断风险素材 |
| M05 / M06 | 授权待核验，补查分别为 verified / expired | 根据补查结果采取不同动作 |
| M07 | 商业合作标签 | 审核需人工确认，即使时段可用也不能默认确认 |
| M99 | 素材库中不存在 | 区分缺字段与未知素材 |

素材、授权登记、规则和排期均为合成数据；封面地址使用 example.invalid，不进行真实图片读取。关键词规则用于演示，不构成对真实内容、版权或平台合规的完整判断。
